## Q1. この関数を説明してください

4×4 の表の各マスについて「そのマスと右隣のマスの和」を求め、次のルールで変換した表を返す。

* 和が偶数 → `0`
* 和が奇数で 10 より大きい → 1の位（`sum % 10`）
* それ以外 → 和そのまま

例: 1行目 `[1, 1, 2, 3]` の場合

| j | 計算 | 和 | 結果 |
|---|---|---|---|
| 0 | 1 + 1 | 2 | 0（偶数） |
| 1 | 1 + 2 | 3 | 3 |
| 2 | 2 + 3 | 5 | 5 |
| 3 | 3 + **undefined** | NaN | NaN |

## Q2. この関数に問題のある部分を教えてください

**右端の列で `map[i][j+1]` が範囲外になる。**

`j` は `0〜3` を回るが、`j = 3` のとき `map[i][4]` は `undefined`。
`3 + undefined` は `NaN` になり、`NaN % 2 === 0` も `NaN > 10` も false なので、結果に `NaN` がそのまま入る。

```
// 現在の戻り値
[[0, 3, 5, NaN],
 [3, 5, 0, NaN],
 [5, 0, 3, NaN],
 [0, 3, 1, NaN]]
```

言語によってはここで例外になる（Java の `ArrayIndexOutOfBoundsException`、Python の `IndexError`）。
JavaScript は例外にならず `NaN` が静かに広がるので、気づきにくい。

### 気づけると加点

* 内側のループが `map.length`（行数）を使っている。行数と列数が違う表では壊れる → `map[i].length` を使うべき
* `sum > 10` の境界: 和が 10 ちょうどのときは偶数なので問題にならないが、ルールが変わると 2桁のまま残る
* 関数名 `total` と処理内容が合っていない
* 表が関数内に直書きされていて、テストしにくい

## Q3. 問題の部分を解決する処理を追加してください

**右端をどう扱うかは仕様次第なので、まず確認してもらうのが理想。** 主に2つの案がある。

### 案1: 右隣がないマスは計算しない（結果は 4×3）

```js
for (let j = 0; j < map[i].length - 1; j++) {
```

### 案2: 右隣がなければ 0 として扱う（結果は 4×4 のまま）

```js
const right = j + 1 < map[i].length ? map[i][j + 1] : 0
const sum = map[i][j] + right
```

## Q4. この関数を汎用的にするための処理を提案してください

* **表を引数で受け取る**: どんな大きさの表にも使え、テストもしやすくなる
* **行ごとの長さを使う**: `map[i].length` で、正方形でない表やギザギザの表にも対応する
* **変換ルールを分離する**: 「隣との和を求める」と「和を変換する」を別の関数にする
* **隣の方向を引数化する**: 右隣だけでなく、下や斜めにも使える

```js
function transformCell(sum) {
    if (sum % 2 === 0) return 0
    if (sum > 10) return sum % 10
    return sum
}

function pairSums(map, transform = transformCell) {
    return map.map(row =>
        row.slice(0, -1).map((value, j) => transform(value + row[j + 1]))
    )
}
```
