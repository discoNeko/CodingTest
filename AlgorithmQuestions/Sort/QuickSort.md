# QuickSort（クイックソート）

難易度: ★★ / 想定時間: 25〜30分 / カテゴリ: [Sort](README.md)

## 問題

整数の配列を、クイックソートでその場（in-place）で昇順に並べる。新しい配列は作らない。言語の標準ソートは使わない。

## 入出力例

| 入力 | 実行後の配列 |
|---|---|
| `[5, 2, 4, 6, 1, 3]` | `[1, 2, 3, 4, 5, 6]` |
| `[1, 1, 1]` | `[1, 1, 1]` |
| `[]` | `[]` |

## ヒント

1. 基準値（ピボット）を1つ選び、それより小さい要素を左に、大きい要素を右に集める（分割）
2. 分割したあと、左右それぞれに同じことを繰り返す
3. 分割は、左から「ピボット以上」、右から「ピボット以下」を探して入れ替えていく

## 解答方針

1. 範囲内からピボットを選ぶ（例: 中央の要素）
2. 左右から走査して、ピボット以上の要素とピボット以下の要素を入れ替え、範囲を2つに分ける（Hoare の分割）
3. 分かれた2つの範囲を再帰的にソートする

### 計算量

* ピボットがうまく真ん中付近に来れば、分割は log n 段で、時間 **平均 O(n log n)**
* ピボットが毎回最小値・最大値になると n 段になり、**最悪 O(n²)**
  * 例: 先頭をピボットにして、ソート済みの配列を渡した場合
* 追加の配列は不要。再帰の深さ分のスタックだけ使う（平均 O(log n)）

## 参考実装

```js
function quickSort(nums, lo = 0, hi = nums.length - 1) {
    if (lo >= hi) return
    const p = partition(nums, lo, hi)
    quickSort(nums, lo, p)
    quickSort(nums, p + 1, hi)
}

// Hoare の分割: [lo..j] がピボット以下、[j+1..hi] がピボット以上になる j を返す
function partition(nums, lo, hi) {
    const pivot = nums[Math.floor((lo + hi) / 2)]
    let i = lo - 1
    let j = hi + 1
    while (true) {
        do { i++ } while (nums[i] < pivot)
        do { j-- } while (nums[j] > pivot)
        if (i >= j) return j
        ;[nums[i], nums[j]] = [nums[j], nums[i]]
    }
}
```

## 深掘り質問

* 最悪 O(n²) を避けるには、どんな工夫がありますか？
  * ランダムにピボットを選ぶ、3つの値の中央値を使う、再帰が深くなったらヒープソートに切り替える（イントロソート）
* 同じ値が大量にあると、どんな問題がありますか？
  * 分割の仕方によっては偏る。ピボットと等しい要素を真ん中にまとめる3分割が有効
* 再帰の深さを O(log n) に抑えるには？
  * 小さい方の範囲だけ再帰し、大きい方はループで処理する
* 言語の標準ソートは、どんなアルゴリズムを使っていますか？
  * 例: Python と Java（オブジェクト）は Timsort、C++ の `std::sort` はイントロソート
