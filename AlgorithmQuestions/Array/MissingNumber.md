# MissingNumber（欠けた数）

難易度: ★ / 想定時間: 15〜20分 / カテゴリ: [Array](README.md)

## 問題

1 から n までの整数のうち、ちょうど1つだけが欠けた配列（長さ n - 1）が与えられる。欠けている数を返す。
配列はソートされておらず、重複はない。

## 入出力例

| 入力 | 出力 |
|---|---|
| `[3, 1, 4, 5]` | `2` |
| `[2, 3]` | `1` |
| `[1]` | `2` |

## ヒント

1. ソートすれば見つけられる。もっと速くできないか？
2. 1 から n までの合計はいくつか？
3. 合計を使うと大きな n であふれる言語では、XOR が使える

## 解答方針

| 方法 | 時間 | 空間 |
|---|---|---|
| ソートして、隣と差が 2 の場所を探す | O(n log n) | O(1)〜O(n) |
| 出現した数を記録する配列（またはハッシュ）を作る | O(n) | O(n) |
| 1〜n の合計 `n(n+1)/2` から配列の合計を引く | O(n) | O(1) |
| 1〜n と配列の全要素を XOR する | O(n) | O(1) |

XOR は `a ^ a = 0`、`a ^ 0 = a` という性質を使う。ペアになる数は打ち消し合い、欠けた数だけが残る。

## 参考実装

```js
function missingNumber(nums) {
    const n = nums.length + 1
    let expected = n * (n + 1) / 2
    for (const x of nums) {
        expected -= x
    }
    return expected
}

function missingNumberXor(nums) {
    const n = nums.length + 1
    let result = 0
    for (let i = 1; i <= n; i++) {
        result ^= i
    }
    for (const x of nums) {
        result ^= x
    }
    return result
}
```

## 深掘り質問

* 32ビット整数の言語で n が非常に大きいと、合計を使う方法では何が起きますか？
  * オーバーフローする。XOR なら起きない（引きながら足す方法でも回避できる）
* 欠けている数が2つなら、どう解きますか？
  * 合計と二乗和の2つの式を立てる、または XOR の結果をビットで2グループに分ける
* 入力が正しくない（重複がある、範囲外の数がある）場合はどうしますか？
