# BinarySearch（バイナリサーチ）

難易度: ★ / 想定時間: 15〜20分 / カテゴリ: [Search](README.md)

## 問題

昇順にソートされた整数の配列 `nums` と、整数 `target` が与えられる。`target` のインデックスを返す。なければ `-1` を返す。
配列に重複はない。言語の標準の検索関数は使わない。

## 入出力例

| 入力 | 出力 |
|---|---|
| `nums = [1, 3, 5, 7, 9]`, `target = 7` | `3` |
| `nums = [1, 3, 5, 7, 9]`, `target = 4` | `-1` |
| `nums = []`, `target = 1` | `-1` |

## ヒント

1. 先頭から順に探すと O(n)。ソート済みであることをどう活かすか？
2. 真ん中の値と比べれば、探す範囲を半分にできる
3. 範囲の端（`lo` と `hi`）が「含む」のか「含まない」のかを決めてから書く

## 解答方針

探す範囲を `[lo, hi]`（両端を含む）として、範囲が空になるまで次を繰り返す。

* 真ん中 `mid` の値が `target` なら見つかった
* `target` より小さければ、`target` は右側にある → `lo = mid + 1`
* 大きければ左側にある → `hi = mid - 1`

毎回範囲が半分になるので、時間 **O(log n)**。

バイナリサーチは境界の扱いで間違えやすい（無限ループ、1つずれる）。範囲の定義をはっきりさせ、ループ条件と更新式をそれに合わせるのが大切。

## 参考実装

```js
function binarySearch(nums, target) {
    let lo = 0
    let hi = nums.length - 1
    while (lo <= hi) {
        const mid = lo + Math.floor((hi - lo) / 2)
        if (nums[mid] === target) return mid
        if (nums[mid] < target) {
            lo = mid + 1
        } else {
            hi = mid - 1
        }
    }
    return -1
}
```

## 深掘り質問

* `mid = (lo + hi) / 2` と書くと、言語によってはどんな問題がありますか？
  * 32ビット整数だと `lo + hi` がオーバーフローする。`lo + (hi - lo) / 2` なら起きない
* 重複があるとき、`target` が最初に現れる位置を返すには？
  * 見つかっても止めずに `hi = mid - 1` として左側を探し続ける（lower bound）
* `target` がないとき、挿入すべき位置を返すには？
* 「条件を満たす最小の x」を求める問題（答えで二分探索）にはどう応用できますか？
